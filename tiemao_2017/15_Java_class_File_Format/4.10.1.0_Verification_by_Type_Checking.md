
### 4.10.1. Verification by Type Checking

### 4.10.1. 类型检查校验

版本号为 50.0 或以上([§4.1](#jvms-4.1))的 `class` 文件，必须使用本节给出的类型检查规则进行校验。

当且仅当一个 `class` 文件的版本号等于 50.0 时，如果类型检查失败，Java 虚拟机实现可以选择尝试执行类型推断校验([§4.10.2](#jvms-4.10.2))。

这是一项务实性的调整，目的是让过渡到新的校验规范更加平滑。许多操作 `class` 文件的工具可能会以某种方式修改方法的字节码，从而需要调整该方法的栈映射帧(stack map frame)。如果工具没有对栈映射帧做必要的调整，那么即便字节码原则上合法(按旧的类型推断方案本应校验通过)，类型检查也可能失败。为了让实现者有时间调整他们的工具，Java 虚拟机实现可以回退到旧的校验规范，但这仅在有限的时间内允许。

在类型检查失败、但改用了类型推断并成功的情况下，预计会有一定的性能损失。这种损失不可避免。它也应作为一个信号，提醒工具厂商其输出需要调整，并促使厂商进行这些调整。

总之，回退到类型推断校验，既能支持栈映射帧在 Java SE 平台中逐步引入(如果版本 50.0 的 `class` 文件中不存在栈映射帧，允许回退)，也能支持 *jsr* 和 *jsr_w* 指令在 Java SE 平台中逐步移除(如果版本 50.0 的 `class` 文件中存在这些指令，允许回退)。

如果 Java 虚拟机实现曾经对版本 50.0 的 class 文件尝试类型推断校验，那么在所有类型检查失败的情况下它都必须这样做。

这意味着 Java 虚拟机实现不能在一个场景下改用类型推断，而在另一个场景下不这么做。它要么拒绝那些无法通过类型检查校验的 `class` 文件，要么在类型检查失败时始终回退到类型推断校验器。

类型检查器强制执行以 Prolog 子句形式规定的类型规则。英文文本以非正式的方式描述这些类型规则，而 Prolog 子句则提供形式化规范。

类型检查器要求为每个带有 `Code` 属性([§4.7.3](#jvms-4.7.3))的方法提供栈映射帧列表。栈映射帧列表由 `Code` 属性的 `StackMapTable` 属性([§4.7.4](#jvms-4.7.4))给出。其意图是每个基本块的开头都必须出现一个栈映射帧。栈映射帧规定了每个基本块开始时，操作数栈的每一项以及每个局部变量的校验类型(verification type)。类型检查器读取每个带有 `Code` 属性的方法的栈映射帧，并使用这些映射生成 `Code` 属性中指令类型安全性的证明。

如果某个类的所有方法都是类型安全的，且它没有继承 `final` 类，那么这个类就是类型安全的。

```
classIsTypeSafe(Class) :-
    classClassName(Class, Name), 
    classDefiningLoader(Class, L),
    superclassChain(Name, L, Chain),
    Chain \= [],
    classSuperClassName(Class, SuperclassName),
    loadedClass(SuperclassName, L, Superclass),
    classIsNotFinal(Superclass),	 
    classMethods(Class, Methods), 
    checklist(methodIsTypeSafe(Class), Methods).

```

```
classIsTypeSafe(Class) :-
    classClassName(Class, 'java/lang/Object'),
    classDefiningLoader(Class, L),
    isBootstrapLoader(L),
    classMethods(Class, Methods), 
    checklist(methodIsTypeSafe(Class), Methods).

```

Prolog 谓词 `classIsTypeSafe` 假定 `Class` 是一个 Prolog 项(term)，表示一个已被成功解析和加载的二进制类。本规范不强制规定该项的确切结构，但要求在其上定义某些谓词。

例如，我们假定有一个谓词 `classMethods(Class, Methods)`，它把上述表示类的项作为第一个参数，并将第二个参数绑定为包含该类所有方法的列表，这些方法以稍后描述的方便形式表示。

当且仅当谓词 `classIsTypeSafe` 不为真时，类型检查器必须抛出 `VerifyError` 异常，表示该 `class` 文件格式不正确。否则，该 `class` 文件就通过了类型检查，字节码校验也就成功完成了。
