Java EE标准很难推销给Spring框架用户
==

### Spring开发者称Spring框架仍遥遥领先于Java EE


尽管Oracle一直想让Java开发者从Spring框架转移到Java EE(Enterprise Edition, Java企业版), 但Spring的拥护者们仍然牢牢坚守在Spring阵营。

本周在硅谷的SpringOne 2GX大会上聚集的大量Spring拥护者, 充分证明了该框架的强悍和受欢迎程度 —— 它从最初起就一直提供企业级Java当初没有的简单易用性。 当然, 从那以后Java EE已经添加了很多Spring早就拥有的功能, 比如依赖注入, 可以用来简化单元测试。

“我最喜欢的还是Spring,” Morten Sorensen说, 他是哥本哈根的一名Java自由顾问。 “我对Java EE有一些偏见, 因为10年前我放弃它时, 它完全是无法使用的。 现在每当我被迫使用它的时候, 仍然觉得它很笨拙。” Sorensen支持Spring创建一致的代码, 例如。 “多年来Spring一直更具前瞻性。” 但他说, 从技术上讲, Spring现在正承受着来自Java EE和[Akka](http://www.javaworld.com/javaworld/jw-05-2013/130508-osjp-akka.html) Scala中间件技术等技术的压力。

甲骨文早就发布过博客, 介绍如何[从Spring迁移到Java EE](http://www.oracle.com/technetwork/articles/java/springtojavaee-522240.html), 最早可以追溯到2011年。 负责监管Spring的公司[Pivotal](http://gopivotal.com/pivotal-products/apps/spring-framework)的官员坚称, Spring仍然具备优于Java EE的技术优势, 并且依然拥有数百万次的下载量。 “Spring就是一台下载机器,” Pivotal的产品营销经理Pieter Humphrey说, 他还指出Spring和Java EE是共生的, Spring支持了很多Java EE。

Pivotal的官员强调, Spring始终站在前沿。 “Spring在创新, 并在Java EE 7甚至尚未触及的领域推进,” 比如大数据、Hadoop、NoSQL数据库支持和批处理, Pivotal的Grails框架项目负责人[Graeme Rocher](http://www.javaworld.com/podcasts/jtech/2009/022609jtech-rocher.html)说。 Rocher说, 与Spring不同, 甲骨文的Java EE在尝试添加新特性时, 会受到行动缓慢的JCP(Java Community Process)的制约。

Spring Framework 4.0预计将于今年年底前发布, 它将与即将到来的Java标准版8(Java SE 8)保持一致, 具备lambda表达式和新API等能力, 并提供Java EE 7的特性, 比如JMS(Java消息服务) 2.0。 Spring 4.0还支持WebSocket规范, 用于实时Web应用中浏览器与服务器组件之间的双向通信。

本周, Pivotal发布了[Spring IO平台](http://spring.io/), 旨在提高开发人员的生产力、集成devops能力, 并支撑新型应用程序, 比如大数据系统。 Spring IO的关键组件包括Foundation, 它提供用于构建企业级应用程序的API和可嵌入的运行时组件; 以及Execution, 它为构建在IO Foundation之上的应用提供特定领域的运行时。 DSR可以独立运行, 无需部署到外部容器中。
